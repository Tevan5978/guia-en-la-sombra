Las Constantes del Laberinto

class Laberinto: CAMINO = 0 PARED = 1 ENTRADA = 2 SALIDA = 3
¿Por qué? Usamos números para representar cada tipo de celda porque:
  • Es eficiente en memoria (un número ocupa menos espacio que texto)
  • Es rápido comparar números que cadenas de texto
  • Facilita el uso de matrices numéricas (NumPy, etc.)

💡 CAMINO = 0 es una constante de clase (igual para todas las instancias)

Generador de Laberintos - Introducción

Algoritmo: Recursive Backtracking (Retroceso Recursivo)

Es una forma elegante de generar laberintos aleatorios que garantiza:

  • Siempre hay un camino desde la entrada a la salida
  • No hay ciclos cerrados (lo que lo hace más difícil)
  • Cada laberinto es único
¿Cómo funciona?
  1. Llenar TODO de paredes (1)
  2. Empezar desde una celda y "excavar" caminos (0)
  3. Cuando nos quedamos sin opciones, retroceder y probar otra dirección
  4. Repetir hasta que todo esté explorado

Función generar_laberinto()

def generar_laberinto(filas, columnas): # Matriz llena de paredes (1) matriz = [[1 for _ in range(columnas)] for _ in range(filas)] _cavar(matriz, 1, 1, filas, columnas) colocar_entrada_salida(matriz) return matriz
Línea 1-2: List Comprehension anidada

Crea una matriz donde TODOS los valores son 1 (paredes). Es el punto de partida.

Línea 4: _cavar(matriz, 1, 1, ...)

Comienza desde la posición (1,1) - no desde (0,0) porque queremos que el borde sea puro

Línea 5-6: Coloca la entrada y salida, y devuelve la matriz

Función _cavar() - La Recursión

def _cavar(matriz, fila, columna, filas, columnas): # Marcar celda actual como camino matriz[fila][columna] = 0 # Posibles direcciones: arriba, abajo, izquierda, derecha direcciones = [(-2, 0), (2, 0), (0, -2), (0, 2)]
¿Por qué (-2, 0) y no (-1, 0)?

Si nos movemos de 1 en 1, terminaremos con celdas sin paredes. Movernos de 2 en 2 deja espacio para paredes entre los caminos.

Movimiento de 2 en 2:
█ █ █ █ █
█ . █ . █
█ █ █ █ █
█ . █ . █
█ █ █ █ █

Los "." son celdas excavadas, "█" son paredes. Nótese el patrón regular.

Función _cavar() - Aleatoriedad

random.shuffle(direcciones) for delta_fila, delta_columna in direcciones: nueva_fila = fila + delta_fila nueva_columna = columna + delta_columna
random.shuffle(direcciones): Mezcla el orden de las direcciones

Sin esto, todos los laberintos se verían igual. Con esto, cada laberinto es único.

Bucle for: Intentamos ir en cada dirección (pero en orden aleatorio)

Para cada dirección, calculamos dónde estaríamos si nos moveríamos

Función _cavar() - Validación

dentro_del_rango = ( 0 < nueva_fila < filas - 1 and 0 < nueva_columna < columnas - 1 ) if dentro_del_rango and matriz[nueva_fila][nueva_columna] == 1:
¿Por qué > 0 y < filas-1?

Queremos que los bordes sean siempre paredes. No excavamos en los bordes.

matriz[...] == 1: Solo excavamos si hay una pared

Si ya es un camino (0), la saltamos. Evita crear ciclos.

Función _cavar() - La Recursión

# Romper la pared entre actual y nueva matriz[fila + delta_fila // 2][columna + delta_columna // 2] = 0 # Llamada recursiva _cavar(matriz, nueva_fila, nueva_columna, filas, columnas)
// 2 (división entera): Encontramos la celda del medio

Si estamos en (1,1) y nos movemos a (3,1), el medio es (2,1). Excavamos esa pared.

Llamada Recursiva: _cavar(...) se llama a sí misma

Continúa excavando desde la nueva posición. Esto es lo que crea la estructura en árbol del laberinto.

Cuando no hay más direcciones válidas, la recursión se detiene automáticamente y retrocede (backtrack).

Operaciones sobre Matrices

¿Por qué un archivo separado para operaciones?
  • Separación de responsabilidades (cada módulo hace una cosa bien)
  • Las operaciones funcionan tanto con objetos Laberinto como con matrices crudas
  • Facilita las pruebas unitarias
  • Reutilizable para otros proyectos
Los tres pilares:
  1. Validación: ¿Esta posición es válida?
  2. Acceso: ¿Qué valor hay en esta posición?
  3. Búsqueda: ¿Dónde está X?

Validación de Límites

def esta_dentro_de_limites(objeto, fila, columna): matriz = _obtener_matriz(objeto) filas = len(matriz) columnas = len(matriz[0]) if filas > 0 else 0 return 0 <= fila < filas and 0 <= columna < columnas
¿Por qué if filas > 0?

Si la matriz está vacía, no tiene filas y acceder a matriz[0] causaría un error.

Rango válido: fila entre 0 y filas-1, columna entre 0 y columnas-1

Es la forma pythónica de verificar límites. Usamos < en lugar de <= porque los índices comienzan en 0.

Obtener Valor de una Celda

def obtener_celda(objeto, fila, columna): matriz = _obtener_matriz(objeto) if not esta_dentro_de_limites(matriz, fila, columna): raise IndexError(...) return matriz[fila][columna]
¿Por qué validar primero?

Evitamos que Python lance un error confuso. Controlamos exactamente qué pasa.

Mensaje de error personalizado: Decimos exactamente qué posición es inválida

Facilita el debugging.

Recorrer la Matriz por Filas

def recorrer_por_filas(objeto): matriz = _obtener_matriz(objeto) for f, fila in enumerate(matriz): for c, valor in enumerate(fila): yield f, c, valor
enumerate(): Nos da tanto el índice como el valor

Es mejor que usar range(len(...)) porque es más legible.

yield vs return: Esta es una función generadora

Produce valores uno a uno (lazy evaluation). Ahorra memoria para matrices grandes.

Ejemplo: for fila, col, valor in recorrer_por_filas(lab): print(fila, col, valor)

Buscar un Valor en la Matriz

def buscar_valor(objeto, valor): matriz = _obtener_matriz(objeto) for f, fila in enumerate(matriz): for c, val in enumerate(fila): if val == valor: return (f, c) return None
¿Por qué devuelve None si no encuentra?

Es el estándar de Python. Permite al usuario saber explícitamente si encontró algo o no.

¿Por qué itera en lugar de usar métodos de lista?

Porque es una matriz 2D y necesitamos ambos índices (fila Y columna), no solo el valor.

Usos: buscar_entrada(lab), buscar_salida(lab) - atajos convenientes

BFS: Breadth-First Search

¿Qué es BFS? Un algoritmo que explora todas las celdas cercanas antes de ir más lejos.

Estructura de datos: Cola (FIFO - First In, First Out)

Es como una fila en el cine: el primero en llegar es el primero en ser servido.

¿Por qué BFS?
  • Garantiza encontrar el camino MÁS CORTO
  • Funciona bien para grillas (como nuestro laberinto)
  • Fácil de entender
Cola: [entrada]
→ Procesa entrada
→ Agrega vecinos a la cola
→ Procesa primer vecino
→ Agrega sus vecinos a la cola
... hasta encontrar la salida

Verificar si Existe Camino - Parte 1

def existe_camino(matriz): entrada = None salida = None for fila in range(filas): for columna in range(columnas): if matriz[fila][columna] == 2: entrada = (fila, columna) elif matriz[fila][columna] == 3: salida = (fila, columna)
Paso 1: Encontrar entrada y salida

Necesitamos saber de dónde empezar y a dónde queremos llegar.

Verificar si Existe Camino - Parte 2

visitados = set() cola = [entrada] visitados.add(entrada) while cola: fila_actual, columna_actual = cola.pop(0)
visitados = set(): Conjunto vacío

Un set es más rápido para verificar "¿ya visité esto?" que una lista.

cola = [entrada]: Empezamos con la entrada
cola.pop(0): Toma el primer elemento de la cola (FIFO)

También podríamos usar `from collections import deque` para mayor eficiencia.

Verificar si Existe Camino - Parte 3

if (fila_actual, columna_actual) == salida: return True vecinos = [ (fila_actual - 1, columna_actual), # arriba (fila_actual + 1, columna_actual), # abajo (fila_actual, columna_actual - 1), # izquierda (fila_actual, columna_actual + 1), # derecha ]
¿Llegamos a la salida? Si sí, devolvemos True.

BFS garantiza que este es el camino más corto.

Vecinos: Los 4 vecinos adyacentes (arriba, abajo, izq, der)

No incluimos diagonales porque un laberinto típico no permite movimiento diagonal.

Verificar si Existe Camino - Parte 4

for vecino in vecinos: vf, vc = vecino dentro = 0 <= vf < filas and 0 <= vc < columnas if dentro and vecino not in visitados: valor = matriz[vf][vc] if valor != 1: # no es pared visitados.add(vecino) cola.append(vecino)
Para cada vecino: Verificamos 3 cosas
  1. ¿Está dentro del laberinto?
  2. ¿Ya lo visitamos?
  3. ¿No es una pared?
Si pasa todas las pruebas, lo agregamos a la cola y a visitados.
